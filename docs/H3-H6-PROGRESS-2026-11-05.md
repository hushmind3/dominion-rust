## H3 — ModelGateway (부분 완료)

추가: `src/engine/gateway.rs`

- 하나의 `Route` 해석: provider id 또는 첫 enabled provider, base URL/secret/model/
  toolMode/reasoningProtocol/local/capability/context·output 한도를 한 곳에서 결정.
- `provider_eligible`: `enabled=false` 또는 `capabilities.text=false` 제외.
- `capability_score`: 선언된 `quality`/`reasoning`을 모델명 숫자 추정보다 우선.
  선언 profile(1..2)과 이름 추정(0..1)을 분리해 항상 선언이 앞선다.
- `ordered_alternatives`: learning → capability → local → id 결정적 정렬.
- `acquire`: base_url별 admission semaphore. 로컬 1, 클라우드 4.
  permit은 SSE 응답 본문을 다 읽을 때까지 유지된다.
- `send`: auth/timeout/1회 재시도 공통 경로.
- `usage_from`/`record_usage`/`record_usage_total`: 호출별 usage를 audit에 기록.
- `disable_thinking`: `capabilities.thinking` 선언 우선, 없으면 기존 local 기본값.

연결된 호출 경로:

| 호출자 | 변경 |
|---|---|
| `chat/provider.rs` | provider 해석을 `gateway::route_from_provider`로 통합, 스트리밍 전 `gateway::acquire` 적용, 종료 시 usage 기록 |
| `engine/llm.rs` | 자체 provider/auth/retry/local mutex 제거, `gateway::resolve`/`send` 사용 |
| `engine/compact.rs` | 자체 baseUrl/auth 요청 제거, `gateway::resolve`/`send` 사용 |
| `chat/runtime.rs` | provider `contextTokens`에 따라 history byte budget 조정, 응답 `max_tokens` 한도 전달 |

검증: `gateway` 단위 테스트 4개(비활성/텍스트 불가, capability 정렬, usage 파싱,
로컬 admission 직렬화), llm 테스트 2개.

실제 실행 증거(격리 4B 실험): `model.usage` audit 12건, `purpose=chat`,
`local=true`, `model=qwen3:4b`가 기록되었다. 스트리밍 호출은 total만 알 수 있어
`estimated=true`로 남긴다.

아직 아님: 하나의 gateway가 스트리밍/비스트리밍을 모두 소유하는 완전한 request
모델, 비용 집계 API, vision/이미지 capability, provider별 동시성 설정 노출.

## H4 — 범용 실행 (부분)

- **클라이언트 연결 종료가 작업을 취소하지 않는다.** `run_turn_with_policy`에서
  `tx.closed()` 취소 분기를 제거했다. 명시적 cancel/timeout만 중단 사유다.
  E2E `closing_the_sse_client_does_not_cancel_background_work`가 실제 SSE 연결을
  닫은 뒤 execution이 completed로 남고 assistant 메시지가 저장되는지 확인한다.
- **실패 분류**: `src/engine/recovery.rs`가 `unknown_external_result`,
  `permission_denied`, `limit_exceeded`, `model_error`, `verification_failed`,
  `tool_failed`, `cancelled`, `execution_error`를 기록한다. finalize가
  `failureClass`/`recoveryHint`를 execution에 남긴다.
- **복구 연결**: goal 반복이 실패하면 `latest_failure_hint`로 해당 task의 최신
  분류·힌트를 gaps에 넣어 replan 입력으로 사용한다.

아직 아님: RunCoordinator 상태 reducer, lease/wake, goal/chat/workflow의 단일
lifecycle 추상화. 현재는 기존 goal job/checkpoint와 turn runtime을 그대로 쓴다.

## H5 — 멀티에이전트/도구 (부분)

- delegate 자식은 부모의 도구 권한을 **약화**해서만 상속한다.
  `toolsEnabled = parent.toolsEnabled && parent.toolsExecutionEnabled`,
  `toolsExecutionEnabled = parent.toolsExecutionEnabled`.
- `task_status`/`task_result`는 job을 만든 세션 또는 그 부모 세션만 읽을 수 있다.
  다른 세션은 `이 작업에 접근할 권한이 없습니다.`로 거부한다.
- 위임 깊이 제한 4. 부모 세션 체인을 따라가며 계산하고 cycle은 방어적으로 끊는다.

아직 아님: 부모 잔여 예산의 정확한 이전, 병렬 자식 결과의 구조적 병합,
MCP 서버 stable id/버전 관리.

## H6 — 기억/경험 (부분)

- memory record에 `revision`을 추가했다. revision은 id/text/type/scope/status의
  content hash이며 updatedAt 같은 비의미 필드를 포함하지 않는다.
- supersede 시 revision을 갱신한다.
- selection snapshot의 memory manifest가 저장된 revision을 사용하고, legacy
  record는 동일 함수로 계산한다.

아직 아님: Hypothesis typed 저장/승격, SharingGrant, 충돌·만료 정책의 전면 통합.
