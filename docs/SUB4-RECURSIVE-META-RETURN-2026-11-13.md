# Sub4 recurring intelligence-to-meta-policy self-rewrite

**Judge feedback addressed:** inventing modules and passing instructions to descendants is not yet an algorithm-level feedback cycle. The missing evidence is that a *recompiled successor* changes its source-editing improvement method and then uses that new method to change the invented intelligence again, repeatedly.

The accepted intelligence role is discovered through `rsi_open_topology::inherited_roles`, so a role may be invented by future source edits. `rsi_recursive_rewrite::ledger` reconstructs a lineage-constrained recurrent state machine for every newly adopted role. It is advanced only when a later recompiled child has an independently revalidated, candidate-backed, source-attributed edit to the improvement method; the *following* accepted child must separately edit the invented role's original source path. All outcomes are revalidated by the existing immutable paired oracle.

The cycle has **no fixed generation limit**: invention → method edit → role re-edit → method edit → ... . The compiled child's `reconfigure` executes that state by re-ranking real source targets and adjusting the active `metaPolicy`, forecast provenance, edit checkpointer and actual model instruction. The method files are discoverable source targets, not prose; they can themselves be modified by subsequent generations. The private detached worktree, frozen evaluation and production deployment boundary are not changed.

Focus areas:
- Real source-level inventions, not role labels, open a recurrent meta redesign obligation.
- An adopted method source revision changes the next descendant's actual target to the originally invented role; its adopted return reopens the method rewrite phase.
- Any inherited explicitly authorized successor schedule or owner-constrained objective retains priority.
- Unknown or unverified descendants, missing role-source attribution, and disjoint commit lineages cannot advance the loop.
- The recursion ledger is persisted in generation records; earlier claims are not mistaken for measured improvement.
- An architecture frontier with only one representative file for `improvement_methods` could never reliably target the actual method code. The compiled frontier therefore includes source-hashed meta-controller and recursive-rewriter files.

**Verification boundary:** Rust unit tests describe the intended contracts; no CI, compiler, reproduction, or measured RSI acceleration is claimed by this commit.

References: Hyperagents (arXiv:2603.19461; facebookresearch/Hyperagents), Mendel Gödel Machine (arXiv:2608.07645), and Hyper Algorithm Design Agent (arXiv:2609.35328). The recurring lineage policy here is new Dominion implementation work, not a reproduction of those reported results.
