# Main의 전체 시스템 RSI 실행 계약

2026-11-12 통합 구현. 제품의 중심은 범용 작업 에이전트와 그 시스템의 재귀적 진화이며, 오류 알림·사용자 수정 요청은 작은 보조 입력이다. Sub3 `0a34968b3bc1`의 재빌드된 후손 실행 경로를 main에 병합하고, Sub2의 구조 탐색과 Sub4의 다중 구성요소 설계 계약을 이 실행 경로에 맞게 재구현했다. 브랜치 전체를 서로 덮어쓰지 않았다.

## 실행 경계

1. 사용자가 등록된 API 또는 로컬 제공자·모델, 목표, 예산을 고른다. DeepSeek는 저렴한 기본 선택일 뿐 시스템 전용 모델이 아니다. 로컬 전용 모드는 유료 제공자로 시작하지 않으며 자동 유료 fallback을 하지 않는다.
2. 감독기가 기준 소스를 고정하고 격리된 Git worktree에서 해당 커밋을 빌드한다. 실행 파일의 실제 커밋과 SHA-256을 기록한다.
3. 그 실행 파일의 `--rsi-plan-generation`이 자기 소스 목록·구조·이전 결과를 읽고 다음 분야, 파일, 검색 정책, 재사용 방법을 정한다. 정상 개선과 후속 A/B는 같은 계획 진입점을 쓴다.
4. 감독기는 전체 소스 지문과 각 경로·해시를 확인한다. 후손의 역할 목록이나 탐색 순위를 원래 정책으로 다시 계산하지 않는다. 새 정책·역할을 발명해도 실제 소스 근거가 맞으면 허용한다.
5. 모델은 실제 소스를 읽고 `rsi_system_plan`으로 가설·구조·대상 파일을 선언한 뒤 편집 도구로 구현한다. 컴파일과 독립 A/B를 통과한 실제 패치만 채택한다.
6. 채택된 커밋을 다시 빌드하고 그 후손이 다음 계획과 작업을 수행한다. 실패·중립 후보·컴파일 오류·읽기 자료·미완성 연구도 인덱스/경험/아카이브에 남겨 다음 실행이 재사용한다.
7. 현재 소스 브랜치에 반영할 때는 기록된 원본 브랜치와 기준 커밋, 커밋별 패치 트리를 대조한다. main에서 시작한 검증된 계보도 반영할 수 있다. 다른 브랜치의 기존 실험이나 미검증 수동 패치는 main에 반영하지 않는다.

알고리즘·개선기·실행 하네스·기억·학습·도구·프론트 소스가 진화 대상이다. 역할 목록은 초기 안내이며 새 역할도 허용한다. 독립 평가기와 채택/출처 검증 경계는 후보 수정 대상에서 제외한다. Git worktree는 소스 격리이며 OS/네트워크 보안 샌드박스는 아니다.

## 가져온 구조

- **Sub2의 구조 탐색:** 구성요소별 현재 소스·SHA·시도 수·검증된 변경 여부를 `architectureFrontier`로 만든다. 모델의 성공 주장만으로 미개선 영역을 닫지 않는다. 선택한 `architectureTarget`을 UI와 세대 기록에 남긴다. 대표 파일은 탐색의 시작점이며 모델의 전체 편집 허용 범위는 아니다.
- **Sub4의 다중 설계:** `component=system`, `components`, `componentFiles`, `targetFiles`로 여러 역할의 결합 변경을 선언한다. 새 모듈을 포함할 수 있다. 각 역할에 실제 대상 파일이 있어야 하며, 선언한 **모든 파일**이 최종 패치에 포함되어야 한다. 일부 파일만 고친 설계를 전체 재설계로 계승하지 않는다.
- **Sub3의 실행 계승:** 감독기의 고정 계획을 후손이 단순 실행하는 구조를 피한다. 실제 채택된 실행 파일에서 계획·도구·문맥·검색·기억/학습·방법 실행을 수행한다.

## 채택과 전체 시스템 증거를 구분

개별 후보는 동결된 원본/후보 검사와 회귀 없는 측정 개선으로 채택한다. 개선기 자체의 후속 능력은 같은 모델·과제·원본·예산으로 두 실행기를 비교하는 네 분야(도구/계획, 기억, 문맥, 개선기) 총 8개 에피소드로 측정한다. 평균 개선이 한 분야의 회귀를 가리지 못하도록 분야별 측정 사례를 별도로 채택 판정에 넣는다. 이는 제한된 후속 과제의 증거이며 전체 지능 척도가 아니다.

전체 시스템 모드의 `systemEvidence.demonstrated`는 다음을 모두 요구한다.

- 독립 영수증을 재검산할 수 있는 모델 작성 시스템 세대 3개 이상의 연결된 채택 계보.
- 직전 채택 커밋과 다음 생성기 커밋의 일치, 서로 다른 실행 파일로 2회 이상 계승.
- 알고리즘·하네스·기억·학습·도구·개선 방법의 소스 변경 범위 충족. 역할 표시는 선언된 소스 범위이며 역할별 지능 향상 판정이 아니다.
- 실제 후속 과제의 측정 개선.
- 이전 세대가 발명한 실행 절차가 후손에서 검증되어 실행되고, 그 절차의 쓰기 영수증이 독립 채택된 소스 해시와 일치. 단순 등록·읽기·함께 실행됐다는 기록으로 대체하지 않는다. 이것도 절차의 성능 기여에 대한 독립적인 인과 A/B 증명은 아니다.

모든 지표는 저장된 후보·실험·도구 영수증에서 계산한다. UI의 기록 조회는 모델 호출 없이 이 증거를 재검산한다. 예전 네이티브 변형기 3세대 성과를 모델 기반 전체 시스템 완주로 승격하지 않는다.

기본 역할과 평가 과제는 초기값이다. `rsi/evaluations`의 운영자 프로필로 새 과제·독립 oracle·필수 역할을 등록하고 시작 시 원문·SHA를 동결한다. UI 고급 설정에서 선택하며 비교 예산도 실제 과제 수에 맞춘다. 후손은 새 역할/구조를 발명할 수 있지만 진행 중인 독립 평가 기준을 자가 변경하지 못한다.

평가 실행기는 Node.js로 통일해 Bash 의존성을 제거했다. Windows/MSVC와 macOS의 동일 소스 루프를 대상으로 CI 매트릭스를 두었다. 소스 승격은 공통이며 현재 실행 파일의 자동 교체·재시작은 macOS LaunchAgent 소스 설치에서만 지원한다. 그 외에는 소스 승격 후 재빌드·재시작이 필요하다.

## 이번 검증의 범위

유료/로컬 모델을 새로 호출하는 실험은 하지 않았다. 로컬 테스트는 소스 사실 검증, 후손의 새 순위/역할 허용, 허위 성공 근거 거절, 다중 파일 구현 완결성, 분야별 회귀 거절, 실제 도구 영수증을 요구하는 계승 판정을 검사한다. 테스트의 합성 실험 영수증은 프로토콜 검증용이며 실제 지능 향상의 실측값이 아니다.

[이전 구조 감사](research/rsi-structure-audit-2026-11-12.md)와 [기존 측정 기록](rsi-completion.md)은 당시 커밋의 역사적 결과다. 이번 main 통합으로 전체 시스템 재귀 성능이 실증됐다는 주장은 하지 않는다. 모델·비용 집행을 후보와 별도 프로세스/OS 경계로 강제하는 부분, 더 넓은 독립 과제와 장기 반복 계승 실증은 남아 있다.
