# 계속 발전하기: 비교·선택·다음 세대

기준: `dominion-sub`, 2026-11-10. 목표를 유지한 연구·구현·비교·세대 계승과, 검증 계보를 4317 작업 브랜치 서버에 반영하는 제품 경로다.

## 사용 화면

모델을 고르고 **발전 시작**을 누른다. 기본은 **내가 선택**이다. 비교가 끝나면 **기존 버전 / 개선 버전**의 정확도·검사 시간·측정된 사용량과 종합 우위를 보여준다. **기존 유지 / 개선 버전 선택**으로 다음 개선의 출발점을 정한다. 측정하지 않은 사용량은 `—`이며, 생성 작업의 토큰 사용량과 구별한다.

**우세한 쪽 자동 선택**을 켜면 독립 비교에서 우세한 후보만 채택한다. 우열 미확인·회귀·빌드 실패는 채택하지 않는다. 사용자는 언제든 **중단**할 수 있다. 작업량은 짧게(3단계·6만 토큰·15분), 보통(6단계·18만 토큰·30분), 넉넉히(12단계·60만 토큰·60분)로 고른다. 연구만 한 단계도 새 근거나 실행 방법이 있으면 다음 구현으로 이어진다. 선택을 기다리는 시간은 실행 시간 예산에서 제외한다. 화면에서 Git·SHA·JSON·개발자 설정을 입력하지 않는다.

선택한 버전은 **다음 자기개선 실행**에 사용한다. 이 단계는 실제 서버 반영과 구분한다. **검증본을 4317에 반영** 버튼은 선택 계보의 모든 커밋을 독립 비교 증거와 대조하고, 별도 Git 인덱스로 검증 패치의 실제 트리를 재구성한다. 현재 `dominion-sub`가 원래 기준 그대로이고 미저장 코드가 없을 때만 fast-forward한다. 별도의 연구 파일은 추가하거나 삭제하지 않으며 `main`은 이동하지 않는다.

반영 작업은 기존 설치 작업 큐를 사용한다. 기존 연구용 빌드 캐시를 재사용해 Rust 실행 파일을 별도 경로에서 준비한다. 실행 파일의 실제 커밋 식별자와 프론트 타입 검사·별도 출력 빌드를 확인한 뒤 화면과 실행 파일을 교체하고, 기존 4317 LaunchAgent만 재시작한다. 빌드 실패나 소스 변경 또는 진행 중 작업이 확인되면 실행 서버를 교체하지 않는다. 포트·서비스 설정을 바꾸거나 원격에 자동 푸시하지 않는다. 현재 실행 커밋이 선택 커밋과 일치할 때만 화면에 실행 중이라고 표시한다.

**같은 목표로 이어가기**는 이전 목표·대상 파일과 저장된 연구를 사용한다. 빈 입력을 새로운 자율 목표로 오해하지 않는다. 중단한 작업이 갖고 있던 이전 검증본도 추가 모델 세대 없이 반영할 수 있다.

## 실제 실행 고리

1. 원본을 별도 Git worktree에 복사한다. 미커밋 소스는 그 복사본 안에서만 스냅샷 커밋으로 만든다. 원본의 수정사항·브랜치·HEAD·연구 자료는 보존한다.
2. 출발 세대에서 `dominion-rust`를 빌드하고, 실행 파일의 컴파일 시점 커밋과 파일 SHA-256을 기록한다.
3. 해당 실행 파일을 `--rsi-worker-job`으로 **실제로 실행**한다. 이 프로세스는 서버·스케줄러·기존 작업 복구를 시작하지 않고 한 세대의 진단·수정만 수행한다.
4. 기존 파일 도구 하네스가 다시 분리한 작업공간에서 패치를 만든다. 자동 모드의 파일 쓰기 허용은 살아 있는 캠페인·세대·해당 작업공간·허용 소스 경로에만 적용한다. 일반 채팅·다른 경로·셸에는 확장하지 않는다.
5. 컴파일/타입 검사 실패는 기존의 최대 2회 수정 경로로 처리한다. 독립 A/B 실행기는 원본과 후보를 각각 컴파일하고 같은 사례를 실행한다.
6. 사용자가 선택하거나 자동 선택 기준을 통과한 후보만 실험 계보에 커밋한다. 다음 반복은 이 커밋에서 새 실행 파일을 빌드하여 실행한다. 부모 ID만 바꾸는 가짜 세대 교체로 처리하지 않는다.
7. 성공·실패·미확정 결과, 생성 모델·커밋·실행 파일 해시·토큰·소요 시간·선택 결과를 보존한다. 다음 작업도 원본이 같으면 마지막 선택 버전부터 이어간다. 원본이 바뀌면 새 원본을 기준으로 시작한다.

개선 대상은 기억·도구·문맥·학습·UI·개선기다. 미탐색 분야를 우선 조사하고, 이후 실제 채택 성과와 생성 비용 및 탐색 횟수에 따른 탐색 보너스로 분야를 고른다. 최근 성공/실패와 측정 결과를 다음 개선기에 다시 전달한다. 모델/제공자 자동 대체는 RSI 세션에서 끄므로 생성 모델을 몰래 바꾸지 않는다.

## 평가 변경

이전 8개 테스트를 회귀 방지로 유지하고, 다음 4개 동결 측정을 추가했다.

| 측정 | 외부 기대값과 실제 관측 |
| --- | --- |
| 기억 검색 | 한국어·영어 질의와 방해 문서에서 정답의 최상위 검색 비율 |
| 장기 상태 회상 | 120개 상태 사이에서 지정한 초기·후기 사실의 회상률 및 문맥 길이 |
| 작업 분해 | 독립적으로 정한 단계 수와 실제 분해 결과의 일치율 |
| 개선 탐색 | 고정한 이전 탐색 이력에서 분야 선택의 기대 행동 일치율 |

`rsi_metrics`는 개선 방향·최소 향상 폭·회귀 허용 폭을 후보 실행 전에 동결한다. 기존 테스트가 모두 통과하더라도 정확도 `0.7 → 0.9`처럼 실제 지표가 좋아지면 향상으로 판정할 수 있다. 잘못된 수치·누락된 관측·부족한 반복·지표 회귀는 통과로 간주하지 않는다.

측정 사례는 양쪽 각각 **6회**, AB/BA 순서를 번갈아 실행하고 중앙값을 사용한다. `cargo`의 컴파일/실행 준비 시간 대신 동결 평가 코드 내부의 실제 작업 시간을 측정한다. 각 변형의 실행 파일과 빌드 경로도 분리한다.

평가 파일과 실행기는 조정자의 컴파일 시점 소스로부터 후보 작업공간 밖에 생성한다. 양쪽에 동일한 평가 파일을 연결하고 실행 전후 SHA-256을 대조한다. 개선기가 자체 평가 코드를 수정하더라도 현재 세대의 동결 평가기를 바꿀 수 없다. 계획·oracle 버전이 다른 후보는 같은 검증 ID를 재사용하지 않는다.

개선기 패치에는 자체 탐색 지표의 향상도 요구한다. 이 탐색 지표는 제한된 고정 행동 검증이며, 모델의 일반 지능이나 전체 연구 능력 향상을 뜻하지 않는다.

기존 A/B 완료 후 적용이 막히던 조건 충돌도 수정했다. 서버가 직접 실행한 비교의 출처·해시·회귀 조건을 확인하며, 검증된 개선기 패치는 별도의 검증 적용 의사와 함께 수동 반영할 수 있다.

## 중단·예산·복구

- 시작 시 화면에서 선택한 자원 상한을 검증한다. 화면 기본은 최대 3단계·15분·60,000토큰이다. 직접 API에서 상한을 생략/0으로 지정한 경우에는 해당 상한이 없으며, 최대 단계 수 기본은 3이다. 캠페인의 누적 토큰 예산을 사용하고 일반 채팅의 별도 250,000토큰 턴 상한을 중복 적용하지 않는다.
- 사용량과 프롬프트 추정치로 다음 호출을 차단하고 출력 상한을 줄인다. 제공자가 사용량을 생략하면 0이 아니라 추정값으로 기록한다. 화면에서도 추정 여부를 구분한다. 제공자 보고가 끝나기 전의 실제 청구량을 정확히 알 수 있는 하드 과금 상한을 뜻하지는 않는다.
- 파일 변경·평가·세대 교체 도중 취소하면 소유한 프로세스 그룹을 정리하고 진행 중이던 세대 기록을 남긴다.
- 프로세스 재시작 뒤 중단된 캠페인을 무조건 재실행하지 않는다. 불확실한 결과는 검토 대상으로 남겨 중복 실행을 막는다.
- 사람의 선택은 비교 회차와 평가 ID에 묶는다. 오래된 화면의 선택이나 상반된 중복 선택은 거부한다.
- 소스 복사는 보안 VM이 아니다. 기존과 같이 승인한 네이티브 코드를 호스트에서 빌드·실행한다.

## 검증과 해석

독립 실행기 테스트에서는 기존 사례가 **전부 통과하는 상태**에서도 실제 경계 조건의 정확도가 향상된 후보를 측정했다. 별도의 통제된 네이티브 작업자 테스트는 원본 실행 파일 → 쌍대 평가 → 실험 커밋 → 재빌드 → 개선된 실행 파일의 다음 세대 실행까지 검사한다. 원본 HEAD와 파일 보존도 확인한다. 이 테스트의 작업자는 통제된 프로그램이며 실제 LLM의 자율 개선 성과로 보고하지 않는다.

브라우저에서는 직접 선택·자동 선택 요청, 비교 버튼, 재접속 후 복원, 중단, 데스크톱/모바일 레이아웃을 모의 API로 검증한다.

검증 결과: Rust 전체 타깃 테스트 **678개**(기초 16 + 엔진 560 + unsafe 감사 3 + 통합 99) 통과, 프론트 타입 검사·빌드 통과, Clippy correctness 오류 0개. 기존 스타일·미사용 경고는 남아 있다. 브라우저에서는 다단계 시작·수동 선택·검증본 반영 요청·새로고침 복원·같은 목표 이어가기와 모바일 화면을 모의 API로 확인했다. 네이티브 통합 검사는 실제 Git 패치 검증·채택·재빌드·후속 실행·작업 브랜치 반영을 수행하며, 조작된 패치와 main 반영을 거부하고 별도 연구 자료를 보존한다. 이 검사의 모델 작업자는 통제된 프로그램이다. 실제 외부 모델을 유료 호출하는 증명용 캠페인은 실행하지 않았다.

이 구현은 계속 실험하고 검증된 결과를 다음 개선에 사용하는 실행 구조다. 실제 모델을 사용한 장기 진화, 9명/100턴 대화, 새 문제 일반화, 세대별 개선 성공률의 가속은 별도로 측정해야 한다. 저장되는 `accelerationProven`은 그러한 증거 없이 `true`가 되지 않는다.
