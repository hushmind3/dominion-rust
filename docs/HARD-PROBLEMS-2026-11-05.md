작성일: 2026-11-05  
기준 커밋: `b6985ba` (`codex/native-memory-harness`)  
검증: 148 unit + 21 integration 통과, GitHub Actions CI 통과

## 1. 한 줄 요약

실행 엔진과 학습 데이터 파이프라인은 동작한다. 그러나 **“학습한 것이 실제 작업 성능을 개선했다”를 인과적으로 증명하고, 모델이 학습한 절차를 실제로 지키게 만드는 부분**은 아직 해결되지 않았다. 이 보고서는 그 어려운 지점을 숨기지 않고 적는다.

## 2. 현재 동작하는 것

- Rust 실행 엔진: 턴 루프, 도구 호출, 승인, 취소, 복구, 증거 게이트, planner/executor/reviewer/repair
- 기억·경험·스킬·전략 저장, 교정 반성(`reflect`), 경험 검색·주입
- `validated` 개선 주입, `shared`/`global` 스코프, 에이전트·채널 간 공유
- 로컬 GGUF(llama.cpp)와 MLX(LM Studio) 로드/채팅
- 웹 UI, 모델 목록, 대화창의 비상세 학습 상태 표시
- 학습 페이지 경계, 교정 감지 확장, 준수 검증을 위한 실행별 주입 ID 기록

## 3. 실제 벤치마크 결과

`scripts/task-benchmark.sh`로 같은 4B 모델·같은 에이전트를 측정했다.

```
baseline: 0
post 3회: 0/3
다른 에이전트: 0
```

원인 분석:

1. 반성 job이 첫 측정 종료 후에 완료되어, 학습 전에 측정한 구간이 있었다.
2. 교정 문장이 모호해 4B가 `before:rule.txt`를 파일 경로로 오해했다.
3. 규칙을 명확히 바꾼 뒤에도, 전략은 실제로 주입됐지만
   (`appliedImprovementIds`에 포함) 모델이 절차를 따르지 않았다.

즉 **저장·공유·주입은 됐고, 준수와 성능 개선은 아직 증명되지 않았다.**

## 4. 해결이 어려운 문제

### 4.1 인과 귀속 (credit assignment)

**증상**: 실행이 `completed`이고 도구 호출이 있으면 전략의 성공 카운터가 올라간다.  
**어려운 이유**: 성공이 그 전략 때문인지, 다른 기억·모델 상태·우연 때문인지 구분할 수 없다. 같은 모델도 출력이 확률적이고, 한 턴에 여러 전략이 동시에 주입된다.  
**필요한 것**: treatment/control 분리, 전략별 실행 격리, 반복 실행, holdout task, 통계적 유의성.  
**현재 임시 대응**: 주입된 개선 ID + 도구 수행 여부만 확인. 인과 증명은 아님.  
**난이도**: 높음. 연산 비용과 실험 설계가 필요하다.

### 4.2 절차 준수 검증 (compliance)

**증상**: “bench 작업 전에 `bench/audit.txt`를 써라”는 전략이 프롬프트에 들어갔지만 4B가 무시했다.  
**어려운 이유**: LLM judge는 비결정적이고, 결정적 검사는 경로·도구처럼 구조화된 절차에만 가능하다. repair loop는 무한 루프·비용·지연 위험이 있다.  
**필요한 것**: 결정적 체크(파일 경로/도구/결과) + LLM reviewer의 하이브리드, repair 예산, 위반 기록.  
**현재 임시 대응**: 실행 기록에 주입 ID를 남기고, 도구 수행이 없으면 검증하지 않는다.  
**난이도**: 높음. 모델 준수 자체가 보장되지 않는다.

### 4.3 장기 작업 성능 평가

**증상**: 단일 벤치마크가 0/3이었고, 반성 타이밍과 문장 모호성의 영향을 받았다.  
**어려운 이유**: 결정적 과제·안정적 환경·충분한 반복이 필요하다. 로컬 4B는 느리고 분산이 크며, 한 번의 성공은 증거가 아니다.  
**필요한 것**: 고정 task suite, 반복 trial, baseline/learned/cross-agent, 신뢰구간, 야간 실행.  
**현재 임시 대응**: 스크립트와 수동 실행. 결과는 아직 음성.  
**난이도**: 높음. 시간과 컴퓨팅이 필요하다.

### 4.4 의미 기반 검색

**증상**: 기억·경험 검색이 토큰 겹침 기반이라 한국어 조사·패러프레이즈에 약하다.  
**어려운 이유**: 임베딩은 의존성·인덱스·지연·프라이버시 비용이 추가된다. 검색 품질 자체를 평가할 데이터도 필요하다.  
**필요한 것**: 로컬 임베딩(Ollama/LM Studio) + 벡터 인덱스 + 하이브리드 재정렬.  
**현재 임시 대응**: 상시 선호 기억, 서명 기반 매칭, 수동 검토.  
**난이도**: 중간~높음. 라이브러리 설치는 가능하지만, 품질 평가가 더 어렵다.

### 4.5 통합·수정·폐기

**증상**: 현재는 중복 제거(`occurrences`)와 300개 초과 `archived` 수준이다.  
**어려운 이유**: “유용성”을 정의해야 하고, 드물지만 중요한 교훈을 잘못 삭제할 위험이 있다. 출처·충돌·정정 이력을 보존해야 한다.  
**필요한 것**: 사용/성공/최근성 기반 utility, merge/supersede 정책, 파괴적 작업은 주인 승인.  
**현재 임시 대응**: `superseded`, `archived`, 감사 로그.  
**난이도**: 중간~높음. 정책 설계 문제다.

### 4.6 전역 공유와 프라이버시

**증상**: 교정 산출물을 `global`로 공유해 채팅·회의실·Discord/Telegram 경계를 넘는다.  
**어려운 이유**: 채널마다 프라이버시 기대가 다르다. 원문이 새면 안 되고, 충돌하는 교훈을 합의해야 한다.  
**필요한 것**: 채널별 opt-in, redaction, 추상 교훈만 전역 공유, provenance, 충돌 해결.  
**현재 임시 대응**: 전역 경험은 원문 대신 작업 서명만 저장. 그래도 기억·전략 텍스트는 전역이 될 수 있다.  
**난이도**: 높음. 기술보다 정책·동의 문제가 크다.

### 4.7 반성 품질

**증상**: 반성은 같은 모델이 자신의 실패를 분석한다. 그럴듯하지만 틀린 교훈을 만들 수 있다.  
**어려운 이유**: 정답지가 없고, 자기 평가 편향이 있다.  
**필요한 것**: 실제 도구 증거 ID, reviewer, 고위험 변경은 주인 승인, 반성 품질 평가셋.  
**현재 임시 대응**: 정확한 원문 인용·도구 ID 검증, 근거 없는 기억 거부.  
**난이도**: 높음.

### 4.8 로컬 모델 한계

**증상**: 1.7B는 학습 JSON을 자주 실패하고, 4B는 thinking에 토큰을 쓴다. 4B도 학습 절차를 무시했다.  
**어려운 이유**: 코드가 아니라 모델 용량·컨텍스트·지시 준수 문제다.  
**필요한 것**: 더 큰 컨텍스트/모델, thinking 제어, 교사 모델, 폴백, 프롬프트 개선.  
**현재 임시 대응**: 4B 교사 모델, 출력 토큰 제한, 로컬 호출 직렬화, 폴백.  
**난이도**: 높음. 하드웨어와 모델 선택에 의존한다.

### 4.9 스킬 자동 활성화

**증상**: 학습된 스킬은 `draft`로 남고 자동 활성화되지 않는다.  
**어려운 이유**: 잘못된 절차가 실제 파일·명령을 망칠 수 있다.  
**필요한 것**: 샌드박스 검증, canary, 롤백, 주인 승인.  
**현재 임시 대응**: 초안 저장 + 수동 검토.  
**난이도**: 중간. 안전 정책이 핵심이다.

### 4.10 크로스플랫폼·패키징

**증상**: macOS 경로·llama.cpp·MLX·launchd 의존성이 있고 Windows 검증이 없다. DMG는 보류.  
**어려운 이유**: 외부 런타임, 서명·notarization, 설치 경로, 권한.  
**필요한 것**: OS별 추상화, Windows 테스트, 패키징 파이프라인.  
**현재 임시 대응**: DMG를 건드리지 않음.  
**난이도**: 중간~높음. 제품화 단계다.

## 5. 우선순위

1. **준수 검증 + 인과 귀속** — 학습이 행동을 바꾸는지 확인하는 최소 조건
2. **장기 작업 벤치마크** — 반복 trial과 baseline/learned 비교
3. **의미 기반 검색 + 통합 정책** — 경험 품질
4. **전역 공유 프라이버시** — 채널 간 학습의 안전 경계
5. **스킬 검증·활성화** — 자동화 범위 확대
6. **크로스플랫폼·DMG** — 마지막 제품화

## 6. 완료 기준 (제안)

- 같은 모델·같은 에이전트가 새 세션에서 **학습 전보다 높은 작업 성공률**을 보인다.
- 그 효과가 **여러 번의 trial과 다른 에이전트**에서도 유지된다.
- 주입된 전략의 **준수 여부**가 실행 기록에 남는다.
- 근거 없는 기억·경험이 저장되지 않는다.
- 실패한 학습은 `rolled_back`/`superseded`로 남고, 삭제되지 않는다.
- CI가 green이고, 벤치마크 결과가 커밋과 함께 기록된다.
