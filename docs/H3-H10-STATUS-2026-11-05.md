# H3~H10 통합 상태 — 2026-11-05

상위 기준: `docs/DOMINION-HARNESS-MASTER-DESIGN.md`
선행 기록: `docs/H0-BASELINE-2026-11-05.md`, `docs/H2-PROGRESS-2026-11-05.md`

이 문서는 H3 이후를 "완료"로 주장하지 않는다. 현재 소스에서 실제로 연결된 것과
아직 연결되지 않은 것을 구분한다. 테스트 개수와 문서 존재는 기능 완료 근거가 아니다.

## 1. 현재 실행 경로 (사실)

```
POST /api/chat
  → run_turn_with_policy
      → episode::revision_for / root_value
      → Store::create_attempt            (root+execution+attempt 원자 커밋)
      → run_turn_body
          → context manifest 수집 (memory/skill/experience/improvement/history/tools)
          → record_selection_snapshot    (PolicyBundle + context + model + completeness)
          → run_harness_nodes            (toolsExecutionEnabled일 때만)
          → model loop
              → dispatch_tool_call       (model/harness 공통 승인·예산·operation)
          → finalize_execution
              → semantic payload hash
              → Store::finalize_once     (execution+improvement+observation 원자 반영)
```

- 모델 도구 호출과 harness 도구 실행 모두 `dispatch_tool_call` 하나를 지난다.
- 승인은 operation-bound이며, 재시작 재개는 task/taskRevision/operationKey/run
  계보를 모두 만족할 때만 1회 소비된다.
- `outcomeUnknown` 도구 결과는 goal/job 재실행 경로에서 `needs_review`로 막힌다.

## 3. H3 첫 단계에서 바꾼 것

- `src/engine/llm.rs`
  - `provider_eligible`: `enabled=false` 또는 `capabilities.text=false` 제공자를
    텍스트 보조 호출 후보에서 제외.
  - `capability_score`: 선언된 `capabilities.quality`/`capabilities.reasoning`을
    모델명 숫자 추정보다 우선. 선언 profile은 1..2, 이름 추정은 0..1로 분리해
    항상 선언이 우선한다.
  - 후보 정렬은 learning → capability → local → provider id로 결정적이다.
  - `disable_thinking_for`: `capabilities.thinking`이 있으면 그 선언을 따르고,
    없을 때만 기존 local 기본값(think=false)을 쓴다.
- 테스트: `capability_profile_wins_over_model_name_digits`,
  `a_provider_may_declare_no_text_support`, `thinking_follows_the_declared_capability`.

이 변경은 D11의 일부다. chat/compact/llm이 하나의 gateway를 쓰는 D10은 아직이다.

## 4. 다음 구현 순서 (의존성 기준)

1. **H3 ModelGateway — 남은 부분**
   - request/admission/usage는 통합됨. 비용 집계 API와 vision capability,
     provider별 동시성 설정을 추가한다.
2. **H4 RunCoordinator**
   - run state reducer, lease/wake, 재시작 안전 재개. 현재 job/goal 상태를 대체하지
     않고 facade 뒤에서 책임을 추출.
3. **H5 협업**
   - delegate 자식에 부모 grant/budget/ACL 상속, worker admission과 child lifetime.
4. **H6 기억**
   - MemoryRevision/Hypothesis/SharingGrant, 충돌·만료·provenance.
5. **H7 평가**
   - frozen manifest, fixture 승인 resolver, blind oracle, 실제 모델 paired 실험.
6. **H8~H10**
   - 실험→승격/롤백 경로는 연결됨. 다음은 자동 실험 scheduler와 canary.
   - H9 메타개선, H10 durable event/운영 안정화는 아직 미시작.
