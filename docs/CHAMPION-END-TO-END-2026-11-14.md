# DOMINION 챔피온: 15개 메뉴 연결 실행 경로 (2026-11-14)

관련 심판 지시: [Issue #9](https://github.com/hushmind3/dominion-rust/issues/9). 이번 변경은 단순 화면 추가가 아닌 **에이전트 협업 작업의 산출물과 검증을 다른 제품 기능에서 그대로 재사용**하는 실행 경로다. 이전에 구현된 자율 목표·영상·RSI·기억 격리·그룹대화는 유지한다.

## 한 가지 사용자 목표가 통과하는 실제 경로

1. **홈** `web/src/pages/Home.tsx`: 현재 모델·에이전트·워크플로 구성에 근거해 다음 실행 기능으로 진입한다. 완료한 워크플로의 실제 단계 수·파일 영수증·토큰 수를 표시한다.
2. **에이전트** `web/src/pages/Agents.tsx` → `agents/WorkflowLauncher.tsx` → `POST /api/agents/:id/workflows/:workflow_id/run`: 담당 단계가 있는 워크플로만 선택·실행한다. `src/api/agents.rs`가 배정 관계를 검사한다.
3. **연결 스킬** `extensions/SkillsPanel.tsx` → `Workflows.tsx`: 활성화한 사용자 설치 스킬을 특정 에이전트 실행 단계에 명시 배정한다. `workflows::pin_skill`이 소유 에이전트 범위·활성 상태·내용을 검증하고 **실행 당시 지침/해시를 작업 입력에 동결**한다. MCP 도구 자체는 기존 정책·승인 게이트를 따른다.
4. **워크플로** `POST /api/workflows/:id/run` → `collections.rs` → `workflows::enqueue_run` → `jobs::enqueue_once`: UUID 요청 키로 중복 네트워크 등록을 막고, 워크플로 정의와 스킬을 작업 생성 시 동결한다. 도중 워크플로를 편집해도 실행 프로그램은 바뀌지 않는다.
5. **엔진** `workflows::run` → `run_quiet_outcome` → 채팅 런타임의 선택된 실제 모델/도구/기억: 각 단계의 **성공한 도구 이벤트, 오류 수, 모델 세션 사용량 차분, 파일 바이트의 SHA-256 영수증**을 남긴다. 앞 단계 출력과 파일 영수증 목록은 다음 에이전트의 `{{previous}}` 문맥으로 전달된다. 본문은 최대 12,000자로 제한하며 파일 품질을 추측하지 않는다.
6. **자동화** `Operations.tsx` → `POST /api/automations` → `jobs::schedule_automations` → `workflows::enqueue_automation_run`: 저장된 다중 에이전트 작업을 반복 일정에 연결한다. 회차별 시각과 자동화 ID로 멱등 작업을 만들고, 진행 중이거나 외부 효과 미확정인 이전 회차와 겹치지 않는다. 반복 모델 비용 동의를 받아야 활성화된다.
7. **활동** `Operations.tsx::JobList`: 실행 상태·완료 단계·파일 영수증 개수·모델 토큰 수를 같은 영속 작업에서 표시한다. 작업/도구 오류와 미확정 외부 효과는 엔진에서 기록된다.
8. **개발자** `Developer.tsx` → `developer/WorkflowArtifacts.tsx` → `GET /api/dev/workflow-artifacts/:id` → `goal_artifacts::verify_current`: 서버가 저장한 성공한 파일 작성 증거만 조회하여 **현재 작업 공간 파일의 실제 SHA**와 재대조한다. 동일·변경·누락·경로 위험을 분리하고 파일 내용은 반환하지 않는다.
9. **워크플로 재사용**: 완료한 실행의 마지막 출력은 워크플로 화면에서 새 작업 입력으로 불러올 수 있다. 새 실행은 새 UUID를 갖고 이전 단계 영수증을 새 성과로 복제하지 않는다.

## 회복·원가의 정확한 의미

- 유료 모델 사용을 허락한 자동화가 예약됐어도 정확한 금액 상한을 가진 것은 아니다. 현재 결과는 공급자 기록 기반 **모델 토큰 수**이며, 실청구 원화/캐시 절감률/성능 향상률은 측정하지 않았다.
- 새 작업은 한 UUID 요청 ID에 하나의 영속 Job을 대응시킨다. 재시작이나 HTTP 재전송으로 같은 작업이 새로 생기지 않는다. 의도적인 다음 회차에는 별도 키가 발급된다.
- 도구 외부 효과가 `running/interrupted/outcomeUnknown`이면 다음 단계 자동 수행은 중단된다. 중단된 워크플로 단계의 승인 후 재개 UI는 이번에 완성하지 않았으므로 `needs_review`에서 사용자가 상황을 검토해야 한다.
- 파일의 SHA가 일치해도 문서·코드·영상의 **의미 품질**과 테스트 성공을 보증하지 않는다. 사용자 요구 수용 테스트/실모델 수행은 별도로 필요하다.
- 정적 UI 호출 계약 테스트, Rust 단위 테스트, 브랜치 HEAD CI와 실제 유료 모델 장기 실행은 서로 구별한다. 신규 모델·API 비용이 드는 실험은 수행하지 않았다.

## 관련 검증

- `src/engine/workflows.rs`: 같은 요청 ID 중복방지, 수정된 워크플로 정의의 영속 동결, 스킬 범위/버전 고정, 출력 인계/토큰 차분
- `src/engine/jobs.rs`: 반복 워크플로 회차별 중복방지·겹침 차단·비용 동의 누락 차단
- `src/engine/goal_artifacts.rs`: 실제 바이트 SHA 재검증, 변경·경로 위험·출처 위조 거절
- `scripts/champion-ui-menu.test.mjs`: 홈→에이전트→스킬→워크플로→자동화→활동→개발자 경로 연결 검사
