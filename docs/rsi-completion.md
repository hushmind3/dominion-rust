# RSI 완료 기준과 현재 상태

이 문서는 "재귀적 자기개선이 완성됐다"를 판정하는 기준과, 그 기준에 대한 현재 측정값을 기록한다.
주장은 저장된 캠페인 기록으로만 뒷받침한다.

## 완료 기준

1. **연속 채택 3세대** — 같은 계보에서 3세대가 연속으로 채택되고, 매 세대 재빌드·paired 테스트를 통과하며 회귀가 0이어야 한다.
2. **held-out 개선** — 생성기가 볼 수 없는 동결 사례로 baseline과 후보를 비교해, 통과율 또는 지표 개선이 확인되어야 한다.
   - `rsi::evaluate_cases`는 `holdout` 사례 2개 이상, `improver` 대상이면 서로 다른 holdout 도메인 2개 이상을 요구한다.
3. **메타 전이** — 개선기 정책 변경이 채택되고 다른 도메인으로 전이되어 held-out에서 확인되어야 한다.
4. **계보 무결성** — 지문이 소스 커밋과 트리를 포함해야 하며, 빈 diff 해시(`e3b0c442…`)면 무효다.
5. **생산 승격 분리** — 채택은 격리 계보에서 끝나고, 생산 반영은 `POST /api/rsi/campaigns/:id/apply` + `APPLY_VERIFIED_CAMPAIGN_TO_SUB` 확인으로만 수행한다.
6. **비용 규율** — 캠페인은 토큰·시간 예산 안에서 끝나고, 채택 1건당 토큰 비용을 기록한다.

## 2026-11-10 수정

- `snapshot_source`가 `git diff HEAD`만 해싱해 깨끗한 체크아웃에서 빈 문자열 해시를 만들던 문제를 고쳤다.
  이제 `HEAD` 커밋 + 트리 해시 + 로컬 diff + 추적되지 않은 파일 내용을 함께 해싱한다.
- `lineage_fingerprint_valid`로 빈 해시를 무효 처리하고, 계보 재사용은 지문이 유효하고 일치할 때만 한다.
- 캠페인에 `acceptedStreak`, `maxAcceptedStreak`, `capabilityDemonstrated`를 기록한다.
  기존 캠페인은 `GET /api/rsi/campaigns`와 `GET /api/rsi/campaigns/:id`에서 세대 이력으로부터 파생 계산한다.
- 기존 `rsi_current`(빈 지문)는 `stale=true`로 표시했다. 새 캠페인에서 재사용되지 않는다.

## 판정

- 메커니즘: 완료. 재귀 루프, 격리 빌드, paired 평가, held-out 게이트, 생산 승격 분리가 구현되어 있고 테스트로 검증된다.
- 능력 입증: 미완료. 연속 채택 3세대와 held-out 개선 수치가 없다. 이 상태를 "지능 증폭 성공"으로 부르지 않는다.


## 2026-11-12 — Sub3 실제 모델 채택과 후손 복구 확장

- 실모델 증거: [GitHub Actions 43103920736](https://github.com/hushmind3/dominion-rust/actions/runs/43103920736). 공개 모델 응답과 DOMINION 도구 실행으로 4세대 수행, 편집 도구 2회·실제 검증 쓰기 2회·후보 2개.
- 4세대에 후보 `rsi-23ea106e...`가 원본/후보 13개 paired 실행을 통과했고, 동결된 planning holdout 정확도가 **0.75 → 1.00**으로 개선됐다. 회귀 0, 채택된 격리 실험 커밋 `130a9b4ca382598fe26208fba7435fca2919a29a`, 최고 연속 채택 1.
- 이 실측 성과는 원격 공개 GitHub 브랜치에 자동 병합된 코드나 **3세대 연속 채택**을 뜻하지 않는다. 실험 작업공간에 커밋한 단일 실제 후보의 독립 성과다.
- 새 Sub3 기능: `src/engine/rsi_compiler_repair.rs`의 compiler-emitted `MachineApplicable` 수정 제안을 *모델이 이미 수정한 Rust 파일*에만 적용하고 재컴파일에 성공한 경우만 남기는 복구 알고리즘. 실패는 byte-for-byte 원상복구하며, 검증된 편집 후 모델 재시도를 소모하기 전에 실행한다.
- `jobs.rs`는 자동 복구 뒤 **전체 Git 후보 diff를 다시 수집**하고 원본의 실패 후보 대신 새 컴파일 합격 후보를 독립 A/B로 넘긴다. 생성기 정책이 모델 재수정 횟수를 선택하는 기존 계승은 유지한다. 이 개입의 영수증은 세대 이력과 감사 로그에 남는다.
- `rsi_evolve.rs`의 opt-in `rsiExpandAfterGain` 기능은 **독립 채택 증거를 가진 세대 이후** 정적 단일 파일을 재수정하는 대신, 동결 평가의 실제 잔여 정확도 결함으로 목표를 바꾸고 재빌드된 후손에서 소스 인덱스를 다시 탐색한다. 무근거 성공·미검증 성능 증폭을 주장하지 않는다.
- 실모델 측정 스크립트는 `maxAcceptedStreak >= 3 && capabilityDemonstrated`를 실제 완료 기준으로 사용한다. 1세대 채택으로 `actualCompletion=true`가 되던 이전 보고 관행을 수정했다.
- 새 코드의 Rust CI 및 실모델 결과는 새 커밋 SHA와 연결해 별도로 확인할 것. 과거 캠페인 43103920736의 성능을 이번 후속 수정의 성능으로 소급하지 않는다.
