## 이번 세션 실제 개선
### 막힌 고리: 연구 뒤 실패를 건너뛰고 오래된 연구를 반복
`src/engine/rsi_evolve.rs::improvement_history`는 기존에는 `newFindings>0`과 활성 연구 지식이 있는 세대만 다음 캠페인에 전달했다. 따라서 **연구 → 코드 구현 미수행/실패 → 새 캠페인** 순서에서도 가장 최근 실패 대신 오래된 발견만 전파해 `implement_research`를 반복시킬 수 있었다.

- `3a5bfbe`: 계승 대상은 **최신 완료 행동**으로 변경. 동일 저장소 파티션·사용자 목표·소스 revision에서 실패한 구현을 다음 계획에 보존해 `change_approach`를 실행. 최신 후보가 있거나 소스가 바뀌면 오래된 연구로 되돌아가지 않음. 컴파일된 부모 계획기, 워커, 비모델 분기에서 최신 실패 피드백을 동일하게 사용하며 정책 시험의 대조군 분리는 유지.
- `8c064e3`: SQLite 레코드 조회가 `createdAt`을 **초 단위**로 덮어써 세대 순서가 잘못될 수 있음을 CI 회귀에서 발견. 완료 시각을 `completedAt` 밀리초 RFC3339로 별도 보존. 새로운 값의 선후관계를 기준으로 실행.
- `d2d2847`: 기존 SQLite UTC 형식과 RFC3339를 모두 파싱하여 실제 시각으로 비교. 서로 다른 형식의 문자열 사전식 순서 문제를 없앰. **전체 CI 731/731 통과**.
- `c8a5113`: 교차 캠페인 소스 선택의 과거 성과 정렬도 동일한 완료 시각으로 통일.

## 미완성과 다음 승부처 (심판의 40점 문턱)
**이번 회차에서는 외부 모델을 통한 실제 새 알고리즘 패치·홀드아웃 품질 향상·재빌드된 2세대 재개를 측정하지 않았다. 점수 상승·RSI 1단계 완주를 주장하지 않는다.** 기존 보존된 기록: 21개 캠페인/41세대/채택 1, 최대 연속 채택 1.

다음 세션 첫 작업: **실모델로 동일 목표·제공자·예산의 대조군과 수정판을 비교한다.** 실험 증거는 이 순서로 남길 것.
1. 동일 Git 소스의 독립 A/B 작업공간·별도 데이터, 동결된 holdout manifest, provider/model·사용량 기록.
2. `rsiImprovementDirective`, `rsiFocusSelection`, `rsiParentContextFit`, `rsiWorkerContextFit`, `execution_operation`을 보아 **재연구 대신 실제 workspace_replace/write를 수행했는지** 측정.
3. 생성 후보의 diff·`candidateId`, 독립 paired holdout baseline/candidate 수치, 실패/회귀 포함 및 토큰 비용을 남김. **채택 1건당 비용·연구→코드 변경 전환율**을 계산.
4. 개선된 바이너리로 다시 실제 코드 패치를 만들어 독립 holdout 개선이 재현되면 2세대, 3세대 계보로 이어감. 다른 작업/모델 전이는 그 뒤.
5. 실패 시 어떤 행동을 했고 왜 실패했는지 추적해 **실행/검색 전략을 직접 수정**할 것. 문서나 조건만 늘리는 방식 금지.
