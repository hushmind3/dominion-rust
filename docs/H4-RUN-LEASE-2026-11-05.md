# H4 RunCoordinator 1단계 — durable run lease (2026-11-05)

H4 전체(RunCoordinator 상태 reducer, lease/wake, 단일 lifecycle) 중 **소유권·생존
신호·재시작 복구**를 실제 실행 경로에 먼저 연결했다.

## 1. 계약

- lease key: `session:{sessionId}`. chat, goal, room, workflow turn은 모두
  `run_turn_with_policy`를 지나므로 같은 lifecycle을 공유한다.
- owner: `instanceId:uuid`. 프로세스가 아니라 **turn 하나**가 소유자다. 같은
  엔진에서 두 turn이 동시에 같은 세션을 소유할 수 없다.
- `expiresAtMs`: TTL 120초. heartbeat가 TTL/3(최소 1초)마다 갱신한다.
- heartbeat는 turn이 승인 대기나 긴 모델 호출로 멈춰 있어도 계속 돈다.
- turn 종료 시 guard Drop이 heartbeat를 중단하고 lease를 삭제한다.
- 엔진 시작 시 `migrations::stale_leases`가 다른 owner 또는 만료 lease를 제거한다.
  이 프로세스는 포트 바인딩과 duplicate-start guard를 통과한 유일한 소유자다.
- 실행 기록은 기존 `interrupted_executions` 마이그레이션이 `interrupted`로
  종결하므로, 재시작 후 lease 회수와 실행 상태 종결이 함께 일어난다.

## 2. 구현

| 파일 | 변경 |
|---|---|
| `src/db.rs` | `acquire_lease`, `renew_lease`, `release_lease`, `release_stale_leases`, `active_lease` |
| `src/engine/lease.rs` | `LeaseGuard` + heartbeat task + Drop release |
| `src/state.rs` | 프로세스 `instance_id` |
| `src/migrations.rs` | 시작 시 stale lease 회수 + audit |
| `src/engine/chat/runtime.rs` | 세션 진입 시 lease 획득, 실패 시 실행 거부 |

## 3. 검증

- `cargo test --release`: **217 unit + 29 E2E + 8 benchmark bin**
- `run_leases_are_exclusive_and_recover_after_crash`
  - 살아있는 lease는 두 번째 owner 거부
  - 다른 owner renew 거부
  - 만료/외부 owner는 시작 시 회수
- `a_session_has_one_live_owner_and_is_released_on_drop`
- `heartbeat_keeps_a_long_turn_alive` (TTL 1.5초, 1.7초 대기 후에도 lease 유효)
- E2E `approval_is_operation_bound_and_survives_restart`
  - 실행 중 프로세스 kill → 같은 data root 재시작 → 승인 → 같은 task 재개 성공.
    이 경로는 시작 시 lease 회수가 없으면 실패한다.

## 4. 아직 아닌 것
