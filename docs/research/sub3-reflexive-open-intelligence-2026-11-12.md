# 서브3 — 자기개선 방법의 후손 재설계와 열린 지능 구성요소 (2026-11-12)

## 심판 73점 피드백에 대한 조치

심판의 현재 기준은 80점 이상에서 CI 진행 자격을 부여한다. 이전 73점 서브3에는 A→B→A 개선 프로그램과 요인별 동결 비교 실험이 있었으나, 개선기 자체를 새로 짓고 다음 후손이 그 개선기를 실제 사용한 뒤 다시 개선하는 **메타 수준의 실험 계보**는 별도 채택 증거로 닫히지 않았다. 또한 실제 코드에 편입된 새로운 지능 모듈의 후손 상속 범위를 강화할 여지가 있었다.

이번 개선은 점수 표시를 바꾸는 작업이 아니다. 심판이 코드로 판별할 새로운 설계·전달·독립 증거를 실제 후손 실행 경로에 추가했다.

## 1. 컴파일된 메타→기능→메타 재귀순환

- 새 파일: `src/engine/rsi_reflexive.rs` (후손이 재작성할 수 있는 일반 Rust 소스)
- **seed**: 모델이 `rsi_meta_controller.rs` 등 실제 메타 개선기 소스를 고치고, 외부 감독자의 동결 평가를 통과해야 다음 단계가 열린다.
- **transfer**: 새로 빌드된 바이너리가 자신이 갱신한 메타 정책을 실행해 기억·학습·모델·하네스·도구 등 별도 지능 구성요소의 코드를 수정한다.
- **return**: 그 구성요소를 개선해 채택된 후손이 동일 메타 개선기로 돌아가 개선 방법을 다시 재설계한다.
- 세 단계가 모두 성공해도 최종 설명은 **독립 채택된 3개 소스 세대의 실제 순환**이다. 무한 RSI나 특정 인과 효과를 근거 없이 주장하지 않는다.
- 각 단계의 `generatorCommit → acceptedCommit`, 실제 `changedSourcePaths`, `acceptedSourceHashes`, `compiledPlanExecuted`, 메타 정책 및 프로그램 SHA를 비교한다.
- 정확히 그 프로그램이 실행되지 않았다면 순환 실적으로 계산하지 않는다. 각 단계가 2회 실패할 경우 해당 소스 버전에서 메타 탐색으로 돌아가 고정 루프를 해제한다.
- 이미 독립적으로 진행 중인 기존 A→B→A `complement/return` 단계, 명시적 작업, 기존 하위 A/B 작업을 임의로 덮어쓰지 않는다.

## 2. 열린 지능 토폴로지와 실제 실행 편입

- 새 파일: `src/engine/rsi_component_birth.rs` (후손이 재작성할 수 있는 일반 Rust 소스)
- `rsi_system_plan`에 새 `newComponents` 계약: `role`, `domain`, `purpose`, `sourcePaths`, `integrationPaths`.
- 새로운 모듈의 소스와, 그 모듈을 기존 실행 경로에 연결하는 **별도 파일**이 실제 패치에 모두 들어 있어야 한다.
- 변경된 양쪽 파일이 독립적으로 재검증·채택되고 소스 해시가 기록된 후에만 새 지능 역할을 후손 `systemBlueprint`에 포함한다.
- 새 후손은 현재 소스 해시를 다시 읽어 새 모듈을 일반적인 지능 개선 탐색 `architectureFrontier`에 포함한다. 예전 제안의 소스 해시를 현재 소스인 것처럼 이용하지 않는다.
- 기존 하네스/알고리즘/모델/기억/학습/도구만을 허용하는 고정 목록이 아니다. 모델이 설계한 동적 역할도 새로운 개입·메타 순환의 대상이 된다.

## 3. 실제 제어 경로

`rsi_evolve::plan_generation_from_file`은 새로 컴파일된 후손 내부에서 재귀 프로그램과 기존 메타 정책을 결합하고, 단계별 단일 소스 개입을 선택한다. 해당 판단은 다음 후손의 `rsiReflexiveProgram` 입력에 인계된다. 외부 코디네이터와 실제 worker 양쪽에서 소스·계보·SHA를 검증한다. 증거는 `rsi_generation.reflexiveProgram`과 `rsi_system::handoff_evidence`에도 연결된다.

새 컴포넌트의 선언은 모델이 직접 `rsi_system_plan`을 제출하고 실제 소스를 편집해야 한다. 제안만 하고 코드를 고치지 않으면 채택되지 않는다.

## 4. 비교한 연구 및 다른 브랜치

- HyperAgents (2026-11-01 개정): https://arxiv.org/abs/2603.19461 및 https://github.com/facebookresearch/Hyperagents — 편집 가능한 작업/메타 개선기의 결합
- Mendel Gödel Machine (2026-08): https://arxiv.org/abs/2608.07645 및 https://huggingface.co/papers/2608.07645 — 다중 궤적·교차 계보 상속
- Huxley-Gödel Machine (ICLR 2026): https://openreview.net/forum?id=T0EiEuhOOL — 현재 지표와 미래 후손 개선 능력의 차이
- SpecForge (2026-10): https://arxiv.org/abs/2610.15708 — 결합된 개입의 다중 경로 탐색
- `dominion-sub4`의 `rsi_open_topology.rs`와 비교하여, 서브3는 **동결 채택된 통합 소스 파일+통합 변경의 이중 증거**를 동적 역할의 직접 입장 조건으로 삼았다.
- 서브3 자체의 `rsi_factorial.rs`는 A 단독/B 단독/A+B 합동 실험을 맡고, 신규 `rsi_reflexive.rs`는 실제 후손에 걸친 메타 개선 순환을 맡는다. 구성요소 간 측정과 세대 간 계승을 서로 다른 증거로 관리한다.

## 5. 검증 경계

Rust 단위 테스트로 3세대 순환, 실제 소스 변경 누락, 소스 SHA 변조, 새 구성요소의 실행 편입 누락 및 미채택 기록의 거부를 정의했다. 테스트 코드가 포함된 사실은 실행 결과와 다르다.

요청한 대로 모든 커밋에 `[skip ci]`를 사용했다. **CI·컴파일·완주 실험을 수행하지 않았으며, 새 심판 점수도 아직 받지 않았다.** 기존 73점은 이전 코드의 심판 판정이며, 새 코드의 실제 점수나 80점 달성을 주장하지 않는다.
