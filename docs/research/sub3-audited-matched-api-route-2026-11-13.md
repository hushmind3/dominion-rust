# 서브3 — API 실행 출처 재생 + 동일 소스·평가 기준 모델 비교 (2026-11-13)

## 왜 바꿨는가

기존 서브3는 세대 요약의 API 실행 증명 플래그와 독립 평가 점수로 모델 경로를 학습했다. 그러나 다음 세대가 실제 모델 사용 기록과 평가 영수증을 다시 대조하지 않으면 오래되거나 손상된 세대 요약이 모델 선택에 부당하게 영향을 줄 수 있다. 또한 다른 generator commit·평가 프로필·기존 과제 상태에서 나온 모델별 성공률은 서로 직접 비교하기 어렵다.

## 구현된 개선

1. 각 세대에 실제 작업 sessionId를 보존하여 작업 ID, 사용 당시 provider/model 및 승인 정책, 사용량 감사 기록의 실제 API 호출·토큰과 대조한다. 감사 로그에서 사용된 전체 모델 경로가 정확히 1개인 세대만 해당 모델에 개선 성과를 귀속한다. 서로 다른 모델이 함께 호출된 세대는 단일 모델 학습 보상에서 제외한다.
2. 독립 평가가 있는 세대는 후보 ID의 보관된 평가 자료와 rsi_pair 원본을 재평가한 지표를 확인한다. 실제 채택된 경우 채택 커밋·베이스 커밋도 확인한다.
3. 증거 재생을 재컴파일 후손 계획 생성, 부모 감독자의 계획 검증, 실제 후손 worker 검증 경로에 연결했다. 출처 식별이 없는 기존 세대 요약은 모델 성능 보상에 사용하지 않는다.
4. 동일 API 세션의 중복 요약을 독립 평가 횟수로 중복 계산하지 않는다.
5. 동일한 generatorCommit·동결 프로필 SHA·holdout 사례 ID·도메인·baselinePass를 공유하는 다른 승인 모델의 평가만 source-matched 비교에 사용한다. 두 모델 모두에서 최소 2개씩의 독립 평가 후보와 2개의 공통 평가 사례가 있을 때 상대 개선 관측값을 모델 경로 선택에 반영한다.
6. 비교 대상이 없어도 기존 사용자 승인 범위 및 기본 모델 유지 원칙이 작동한다. 실험은 기존 승인된 후보로만 제한된다.

## 적용 경로

- src/engine/rsi_api_route_learning.rs : audit/paired receipt 재생, source-matched 사례 비교, 비교 기반 모델 선택, 반례 테스트.
- src/engine/rsi_evolve.rs : 후손·감독자·worker 검증과 작업 세션 ID 보관.

## 근거 수준

source-matched 비교는 원본 소스 커밋·평가 기준을 일치시키는 관찰적 비교다. 모델마다 생성한 패치와 추론 문맥이 달라 순수 모델 품질의 인과적 A/B라고 주장하지 않는다. 외부 API 모델 가중치는 수정·훈련하지 않는다. 이 구현의 진화 대상은 도미니언의 API 실행 선택 정책과 후손 학습 알고리즘 자체다.
