# Champion — repair blocked self-improvement and separate native/model evidence

Date: 2026-11-13. Latest external judge at this turn: **65/100, rank 5**, with −10 for a hard-coded source-branch blocker and −3 for treating zero-model-call native mutation runs as equivalent to model-authored improvements.

## 1. Runtime unblock

The previous `rsi_work_branch()` recognized only `dominion-sub` and `dominion-sub3`, so `dominion-champion` could not use ordinary `rsi_worktree::prepare`, `compare`, `apply_to_sub`, or `apply_campaign_to_sub`.

The new policy:

- Allows **`dominion-champion`**, plus the old `dominion-sub` legacy checkout for explicitly supported old local experiments.
- Explicitly **rejects `main`, every sibling `dominion-sub1` through `dominion-sub4`**, and deceptive variations.
- Reuses `owns_application_branch` at the very **start of an ordinary detached preparation**. The checkout branch must match the job's recorded `rsiSourceBranch` exactly; missing branch provenance is allowed only for the historical legacy checkout, never for new Champion attempts.
- Applies the same predicate in ordinary re-evaluation, in explicit manually reviewed application, and in recorded campaign application. Source path, source commit, candidate patch hash, independent evaluator receipt and cleanliness checks remain intact.
- Keeps the dedicated `rsi_evolve::campaign_source` detached-lab exemption, which already authenticates source/build identity independently.

The real local Git worktree integration test now **creates a `dominion-champion` checkout**, explicitly checks rejection of a sibling checkout with the same base commit and rejection of missing campaign source provenance, then continues detached patch capture and explicit manual apply. (Test authored; CI intentionally not run below 80 points.)

## 2. Zero-model-call source attribution

`rsi_worktree::finish` now refuses to register a model-driven source candidate unless **both** a stored `model.usage` audit for the session and a **completed, model-origin, verified source write tool receipt** are present. Merely modifying a detached worktree (or passing compilation) cannot mint model-driven candidate evidence.

Native source edits generated by `rsi_mutation` have their own path and must carry the existing matching native mutation receipt; they remain separately eligible for independent paired evaluation.

`rsi::model_driven_generation_provenance` is a separate public proof gate: the candidate must be accepted, have real model calls, verified source writes, and a recorded model-origin tool write with exactly the SHA-256 bytes listed in the final independently adopted source hash set. The public campaign audit now reports:

- `capabilityDemonstrated`: independently tested, accepted **source-code** multi-generation development (including native mutations).
- `modelDrivenCapabilityDemonstrated`: the same adopted, transferred, independently evaluated chain **and** actual model invocation and final-byte model edits in every credited generation.
- Per-generation `modelProviderCalls`, `sourceImprovementOrigin`, and `modelDrivenSourceWriteProvenance`.

The coordinator records `modelDrivenIndependentProof` and `nativeIndependentProof` separately. `edit_method_reward` never learns a positive model-editor reward from a zero-call pseudo-model candidate. `rsi_model_lineage::independent_task_receipt` requires actual model call counts, verified source writes, the candidate's original model identity, and replayed independent A/B metrics to learn which approved API/local **improvement agent** generates better descendants. The foundation model weights themselves are not claimed to have changed.
