# 서브3 — 캠페인 간 복구 가능한 Pareto 아카이브와 후손 계승 (2026-11-13)

## 심판 피드백과 수정 목표

2026-11-13 심판은 서브3의 `rsi_archive.rs`가 현재 캠페인의 이력만 읽는 구조를 지적해 -3점을 적용했다(서브3 76점). 이전 캠페인의 검증된 중립 탐색 후보와 실제 후손 시도 횟수가 다음 세대의 계획·재시작 이후 학습으로 이어지도록 수정한다.

## 원본 구조 비교 및 변경

메인 `dd6089a`의 영구 아카이브: 원본 소스 커밋 + 동결 평가계획 + 오라클 소스 해시로 저장 대상을 분리하고, 보관된 후보를 후보별 실제 paired receipt로 재평가한다. 후보의 Pareto 성능과 계보별 후손 시도 횟수는 다음 후보 선택에 반영한다.

서브3 추가 구현:

1. `rsi_archive::select`는 `rsi_generation`의 모든 영구 이력과 현재 캠페인 이력을 함께 검사한다. 재시작 전 평가 후 아카이브 저장이 이루어지지 않아도 봉인된 후보와 평가 영수증이 보존돼 있다면 자동 복구한다.
2. 후보는 기존 `rsi_candidate` 및 `rsi_pair` 영수증으로 매번 재검증하고, 오라클 바이트 해시·평가 계획·원본 커밋이 일치할 때만 다음 세대 탐색에 포함한다. `rsi_archive` 포인터의 후보·패치 해시·저장 ID도 재확인한다.
3. 채택되지 않은 중립 패치만 stepping stone으로 사용한다. 현재의 소스 커밋을 자동 채택하지 않으며, 후손은 원본 기준 커밋에 대해 동결된 A/B 평가를 다시 통과해야 한다.
4. 후손 시도 횟수는 캠페인 경계를 넘어 실제 `jobId`를 중복 제거해 누적하며, 여러 Pareto 후보 중 덜 탐색한 대안을 결정적으로 선택한다.
5. 컴파일 후손이 만든 아카이브 선택은 부모 감독자 `rsi_evolve.rs`, 실제 재컴파일된 후손 worker, 그리고 worktree의 실제 패치 적용 직전에 `rsi_archive::valid_selection`으로 원본 기록과 대조된다. 부정확한 선택 JSON은 다음 세대의 실행 후보가 될 수 없다.

## 실제 호출 경로

- `plan_generation_from_file`: 재컴파일 후손이 영구 아카이브에서 비교 가능한 후보를 선정한다.
- `run_loop`: 감독자는 후손 선택 후보의 패치·원본 커밋·오라클·저장된 평가 영수증을 검증하고 자식 job에 계승한다.
- `worker`: 전달된 후보가 컴파일된 계획과 일치하며 영구 저장된 영수증을 재생할 수 있는지 재검증한다.
- `rsi_worktree::prepare`: 분리 작업공간에서 패치를 실제 적용하기 직전 영구 아카이브 원본 결속을 검증한다.
- `rsi_generation`: 실제 자식의 `inheritedCandidateId`·`jobId`를 다음 캠페인에서 다시 읽을 수 있게 기록한다.

## 반례 및 경계 테스트

`src/engine/rsi_archive.rs`에는 기존 Pareto 선택·위조 평가 차단 검사를 유지하고, 다음 경우를 추가했다.

- 별도 아카이브 저장 없이 이전 세대의 영구 기록만 남긴 후 DB를 재개방해 후보를 복구
- 다른 캠페인의 실제 후손 시도를 DB에 기록한 후 재개방해 덜 탐색한 후보 선택
- 저장된 아카이브 포인터의 패치 SHA를 바꾸면 복구 거부
- 후손 선택 내 원본 커밋·오라클 해시·패치 해시를 변조하면 계승 거부

동결 평가기가 달라지거나 원본 소스 커밋이 바뀐 후보는 재사용하지 않는다. 지속되는 것은 **검증 가능한 탐색 지식과 시도 횟수**이며, 특정 후보의 실제 지능 개선이 증명된 것은 아니다.
