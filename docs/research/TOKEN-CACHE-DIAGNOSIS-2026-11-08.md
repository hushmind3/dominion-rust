# 토큰 비용 재조사 — 미해결

운영 코드 수정·재시작·메시지 전송 없음. `dominion-sub` 유지. 정체성·페르소나·원문을 줄이지 않았다. 아래 결과는 해결 또는 운영 비용 절감의 증거가 아니다.

## 자동 학습을 켠 격리 엔진

운영 DB를 별도 임시 디렉터리로 복사하고 기존 작업·승인·실행·예약 실행 대상을 제거했다. 기존 방 ID, 9명, 기억, workingView를 유지했다. 도구 및 자동 학습 활성화. 대화 모델은 gpt-6-luna, 추론 low. 세 번의 `안녕`을 격리 방에 제출했다.

| 회차 | 대화 입력 | 캐시 읽기 | 신규 입력 | 출력 |
|---|---:|---:|---:|---:|
| 1 | 21,642 | 1,920 | 19,722 | 280 |
| 2 | 23,339 | 6,272 | 17,067 | 303 |
| 3 | 24,860 | 16,768 | 8,092 | 241 |

27회 대화 호출 모두 캐시 쓰기 0, 추론 토큰 0을 제공자가 보고했다. 후속 18회 모두 이전 입력 항목 전체가 다음 요청의 동일한 접두사였고 instructions도 같았다. 27회 모두 rebaseReason=null. **이 표본의 캐시 실패는 문맥 재구성으로 설명되지 않는다.** 이것이 다른 운영 상황에서도 재구성이 없다는 증거는 아니다.

학습은 별도 8회 요청을 발생시켰다. HTTP 400 다섯 번, 200 두 번, 429 한 번. 성공한 두 호출의 보고 입력은 2,708, 출력은 131토큰이다. 학습의 캐시 읽기·쓰기·추론 상세 및 실패 요청 사용량은 미보고이므로 0으로 간주하지 않는다. 방 학습 작업 두 개 완료, 한 개 실패. 학습을 포함한 전체 비용 검증을 통과한 실행이 아니다.

제약: 사용량 관측을 위한 로컬 전달 프록시가 제공자 URL 및 그로부터 파생되는 경로/캐시 ID를 바꾼다. 운영 그대로의 비용 측정으로 해석하면 안 된다. 기본 요청은 그대로 전달했고 본문이나 인증정보는 증거 파일에 저장하지 않았다.

## 캐시 옵션

고정 문맥 3회 기본 요청: 입력 1,840씩, 캐시 0 → 1,664 → 1,664. `prompt_cache_retention=24h` 및 `prompt_cache_options.ttl=30m`은 각각 HTTP 400. 제품에 반영하지 않았다. 일반 API 문서의 지원을 이 OAuth 모델 경로의 지원으로 간주하지 않는다.

## 세션 헤더 비교

공식 Codex 소스는 `session-id`/`thread-id` 헤더를 사용한다. DOMINION은 `session_id`를 사용한다. 다음은 **session 헤더 이름만** 비교한 실험이며 전체 Codex 클라이언트 비교가 아니다.

출처: https://github.com/openai/codex/blob/main/codex-rs/codex-api/src/requests/headers.rs

아인즈·샬티아·아우라 각각 6회 × 2방식. 각 방식의 첫 호출을 제외한 합계:

| 헤더 | 후속 호출 | 캐시 적중 | 입력 | 캐시 읽기 | 신규 입력 | 출력(추론 포함) | 추론 |
|---|---:|---:|---:|---:|---:|---:|---:|
| session_id | 15 | 13 | 36,885 | 29,056 | 7,829 | 341 | 141 |
| session-id | 15 | 10 | 36,905 | 22,400 | 14,505 | 536 | 320 |

캐시 쓰기는 모두 0. 확인어 정확 일치는 각각 15/15, 14/15. 두 방식의 캐시 범위는 분리했으며 생성 답변 차이로 후속 입력 크기가 달라질 수 있다. 표본이 작아 어느 헤더가 일반적으로 우수하다고 결론 내리지 않는다. **헤더 변경의 비용 개선은 확인되지 않아 제품 미반영.**

## 현재 결론

문맥 연속성과 비용 절감은 구분해야 한다. 문맥을 그대로 이어 보내도 캐시 0이 발생한다. 지원되지 않는 캐시 옵션이나 효과가 입증되지 않은 헤더 변경을 해결책으로 배포할 근거가 없다. 제공자만의 문제로 확정할 수도 없다.

다음 조사에서 이 실험을 해결 사례로 재사용하지 말 것. 다른 클라이언트를 비교하려면 동일 모델·페르소나·문맥뿐 아니라 실제 전송 계약과 모든 모델 호출의 사용량을 비교해야 한다. 원본 응답 보존, App Server 도입 또는 새로운 연결 방식의 안정적인 절감은 여전히 입증되지 않았다.
