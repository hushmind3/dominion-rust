# 서브3 — 외부 API 기반 지능의 실행 전략을 학습·재설계하는 RSI

**2026-11-13 / 심판 정정 기준 서브3 63점, 2위**

## 무엇을 고쳤나

심판은 LoRA 기반 로컬 모델의 일부 성능 향상과 DeepSeek 같은 외부 API를 사용한 도미니언 전체 RSI 발전을 동일하게 보았던 점수를 회수했다. 현재 `dominion-sub3`는 LoRA 추가 커밋을 제거한 `7a89d57`에서 출발했다. 이번 개선은 **API 가중치 학습을 시도하지 않는다.** 실제 개선하는 것은 도미니언의 모델 선택·추론·도구 운용·기억·코드 개선 방법이다.

### 실제 코드

- `src/engine/rsi_api_route_learning.rs`: 컴파일된 후손이 직접 실행하는 API 모델 경로 학습기. 기존 DeepSeek 등 API 모델의 가중치 변경은 전혀 없다. 소유자가 이미 등록하고 `approvedApiRoutes`로 다시 승인한 정확한 제공자·모델 조합만 후보로 삼는다. 사용자가 승인하지 않으면 원래 모델을 유지한다.
- `src/api/rsi.rs`: 자동 RSI에 명시적 `allowAdaptiveApiRouting: true`와 `approvedApiRoutes`를 제공해야 활성화. 제공자에 원래 모델 또는 `rsiApprovedModels`로 등록된 모델만 허용하고 모델 ID를 환각해서 생성하지 않는다. `localOnly`도 그대로 지킨다. 비승인 시에는 단일 원본 API 경로 그대로 사용한다.
- `src/db.rs`: 정확한 세션·제공자·모델의 `model.usage` 감사 기록을 가져와 실제 호출 및 토큰 사용을 검증한다. 단순한 모델 선택/선언은 모델 사용 증거가 아니다.
- `src/engine/rsi_evolve.rs`: 재컴파일된 후손의 `plan_generation_from_file`이 **독립 평가 결과 + 실제 API 실행 이력**으로 다음 세대의 API 모델을 선택한다. 상위 감독자는 승인 목록 및 계획 SHA를 검증하고, worker는 자기 바이너리의 원리 학습 함수로 동일 선택을 다시 검증한다. 선택 결과가 실제 새 세대 `providerId/model`에 적용되고 `apiRoutePolicy`·`apiRouteUsage`·`apiRouteExecutionVerified`가 세대 기록에 이어진다.
- `src/engine/rsi_system.rs`: 소스 자기모형과 후손 지능의 실행 증거에 API 모델 학습 메커니즘을 편입하며, **실제 코드 품질 평가와 모델 간 본질적 인과 우월성**을 구별한다.
- `src/engine/rsi_principle_learning.rs`: 모델 가중치 학습으로 오도하던 문구를 제거하고 실제 API 실행·라우팅·도구·기억·계획 알고리즘의 발전을 지시한다.

### 독립 검증을 배운 실행 원리로 변환

1. 사용자가 정한 원래 API 모델로 RSI 소스 수정 작업을 수행한다.
2. 보호된 Git worktree의 독립 평가에서 과제별 개선·회귀가 관찰된다.
3. 후손이 실제 모델을 호출했는지 감사 기록과 대조한다. 호환되지 않는 다른 제공자 사용이나 네이티브 무모델 소스 변이는 해당 API 모델의 보상으로 집계하지 않는다.
4. 동일 승인 모델 후보들의 **관찰된 과제 개선**과 회귀 빈도를 이용해 후손의 실행 모델을 선택한다. 같은 평가기 증거가 전혀 없으면 원래 모델을 유지하고, 이미 증거가 쌓인 후에만 사용자가 승인한 다른 모델을 제한적으로 실험한다.
5. 이 라우팅 알고리즘 자체는 `rsi_api_route_learning.rs`이라는 일반 Rust 소스다. 모델이 새로운 평가·메모리·도구 전략을 발명하면 이 코드도 후손이 수정·독립 평가·채택하여 개선할 수 있다.
6. 다음 세대의 실제 API 실행/소스 과제 개선을 다시 관측하여 보상/회귀/예측 오차를 학습한다.

**측정의 한계는 코드에 명시한다.** 각 모델이 서로 다른 소스 패치를 작성하고 기존 보호된 평가기로 비교한 결과는 *도미니언 API 코딩 작업의 관찰된 품질 신호*다. 이것을 API 모델 가중치의 향상이나 동일 프롬프트의 엄밀한 모델 A/B 우열 증명으로 부풀리지 않는다.

### 2026년 동적 모델 등록과 운영 주의

[DeepSeek 공식 모델 API](https://api-docs.deepseek.com/api/list-models/)는 `GET /models`로 현재 지원 모델을 제공한다. 2026-11 공식 문서 기준 `deepseek-flash`와 `deepseek-v4-pro`가 사용된다. 오래된 `deepseek-chat`·`deepseek-reasoner`라는 API 모델 ID를 코드에 기본값으로 박아 넣지 않는다. 사용자가 이미 등록한 정확한 이름만 요청한다. [모델/도구 지원](https://api-docs.deepseek.com/api/create-chat-completion/)을 참고한다.

확인 가능한 코드상의 초점은 **모델을 학습하는 것이 아니라, 사용 가능한 모델로 작동하는 지능 전체가 더 뛰어나게 학습하고 계속 자기재설계하도록 만드는 것**이다.

### 상태와 다음 검증

- 생성·수정된 Rust 소스 및 관련 반증 테스트는 GitHub 서브3 브랜치에 저장했다.
- Rust 컴파일·단위 테스트·실제 DeepSeek API 유료 요청·장기 RSI 완주는 **실행하지 않았다**. 80점 자격, 모델 성능 상승 또는 RSI 완성 여부를 주장하지 않는다.
- 모델 간 엄밀한 비교에는 **같은 동결 입력을 각 API 경로에 따로 실행하는 직접 paired inference**가 추가로 필요하다. 현재의 관측 기반 모델 경로 추정과 혼동하지 않는다.
