## 기존 구현과 한계

이전 인계 및 코드 확인에 따르면 continuity.rs는 세션·봇별 participant_conversation에 workingView를 저장한다. 전송했던 문맥 뒤에 새로운 출처의 메시지를 추가하고, 저장된 답변을 확정하며 재시작 후에도 복구한다. 계약·증거 변경, 대화 초기화, 이력 한도 초과 등의 경우에는 문맥을 재구성한다. 원문은 별도로 보존한다.

하지만 Codex 요청은 instructions와 선택된 전체 input을 다시 전송한다. 자기 답변은 텍스트로 재구성한다. 원격 응답 ID와 native output/encrypted reasoning을 지속 저장·재생하는 구현은 없다.

논리적 대화 연속성은 구현돼 있으나, 그것이 반복 신규 입력 비용 해결을 의미하지 않는다. 캐시 키 유지, HTTP 200, 테스트 통과, 일부 캐시 적중도 해결 증거가 아니다.

이 실험은 사용량을 관찰하려고 로컬 전달 프록시를 사용했다. 제공자 URL과 파생 경로/캐시 식별자가 달라지므로 운영 비용 그대로의 측정이 아니다. 학습도 모두 성공하지 않았다. 전체 운영 비용 검증을 통과한 결과가 아니다.

## 이번 작업의 잘못

사용자는 하네스가 문맥과 상태를 자동 관리해 비용 문제를 해결하기를 요구했다. 이번 작업은 제공자 캐시 옵션과 전송 헤더 비교에 치우쳤다. 하네스의 문맥 선택·중복 제거·상태 갱신 알고리즘을 개선하지 못했다. 따라서 사용자 요구를 해결하지 못했다.

알고리즘을 바꿔도 소용없다는 결론은 내릴 수 없다. 이번에 확인한 것은 동일한 문맥 접두사를 유지하는 것만으로 안정적인 절감을 보장하지 못한다는 사실이다. 제공자만의 문제라고 확정할 근거도 없다.

## 남은 사항 — 실행한 작업이 아님

하네스가 실제로 어떤 내용을 반복 선택·추가하는지, 불필요한 중복이 있는지, 필요한 대화·정체성을 보존하면서 상태를 더 효율적으로 갱신할 수 있는지는 남아 있다. evidence_digest의 confidence/importance/revision/supportingCases 등의 갱신이 내용 변화 없이 재구성을 유발하는지도 입증하지 못했다.

원본 응답 상태 보존이나 App Server 도입이 비용을 안정적으로 줄인다는 증거도 없다. 이들을 해결책으로 확정하거나 무조건 구현하지 말 것.

후속 구현을 별도로 요청받으면 하네스 알고리즘을 대상으로 기존 구현과 동일 조건에서 비교해야 한다. 정체성과 원문 보존, 대화 연속성, 재시작 복구, 전체 입력·캐시 읽기·쓰기·신규 입력·출력·추론·별도 학습 호출을 함께 확인해야 한다. 개선이 입증되지 않으면 푸시하지 않는다.
