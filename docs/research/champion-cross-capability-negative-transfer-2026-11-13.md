# Champion — independently replayed whole-intelligence negative transfer

**Date:** 2026-11-13. **Judge snapshot before implementation:** Champion / Sub3 / Sub4 tied on 79/100. No subsequent score or empirically completed RSI is claimed.

## Why the loop needed this

Champion already has reciprocal intelligence graphs, inherited improvement-method families and code-editing descendants. However, its source-level improvement agenda did not promote **repeated damage to a previously passing different capability** to a concrete, two-file downstream repair. One component could be strengthened at the expense of another while the next child continued rewriting an easy-to-edit meta controller.

Sub1's latest whole-agent work identified this kind of negative transfer, but its source uses a different receipt convention (`holdoutEvidence`). Champion's actual frozen evaluation stores `rsi_pair.report.cases` and recomputes `rsi_candidate.evaluation.metrics.measurements`. The implementation here uses Champion's own **original independent paired receipt replay** rather than copying a mismatched data assumption.

## What is implemented (executed-source integration)

1. **New descendant-editable algorithm** `src/engine/rsi_negative_transfer.rs`. A separate actual source file must be changed in each candidate. The learner infers the unique changed source role from the SHA-pinned architecture frontier. Ambiguous/multi-file interventions cannot claim isolated interference.
2. **Original receipt replay:** `rsi::replayed_pair_metrics` recomputes frozen paired outcomes from `rsi_pair` before a candidate changes the policy. The outcome must match the archived candidate and generation. A model-written narrative, JSON mutation, or a build alone produces no evidence.
3. **Same-source, same-profile grouping:** candidates must share the exact `generatorCommit`, `evaluationProfileSha256`, edited source role and victim capability role. At least **2 distinct candidate IDs** and **2 distinct previously passing damaged holdout case IDs** are required.
4. **Current source horizon:** repeated damage on an old accepted source version remains useful *history*, but cannot force edits to an already-replaced source. Only a cohort tested on the **current compiled generator commit** can become an active intervention.
5. **Actual descendant source targeting:** `rsi_evolve::plan_generation_from_file` makes the victim and suspected source the top two indexed, SHA-anchored focus files and chooses the victim capability domain. This applies ahead of an unmeasured improvement-algebra rule and older stage machinery. Owner-selected objectives and independently pinned post-adoption targets retain precedence.
6. **Parent and child verification:** the supervisor validates the source paths, both ranked source hashes and the candidate cohort structure. The rebuilt descendant recomputes the entire plan from the original candidate receipt store before using it in its real model prompt. Mismatched worker/controller copies or forged source pairs abort.
7. **Next-generation task instruction:** the model is asked to compare source-only, victim-only and joint changes against the same frozen evaluation before judging which intervention restores capability. Rejected candidate regressions are **not** described as adopted intelligence regressions.
8. **Inheritance:** the plan is stored in `rsi_generation.negativeTransferPlan`, and the implementation file itself appears in the mutable scientific-method role inventory. Children can rewrite both the intelligence component and the algorithm used to discover and repair this failure class.

## Added regression cases (authored, not yet run)

- Ordinary fake or non-holdout failures are not negative-transfer proof.
- One candidate or one damaged case cannot force a two-file repair.
- Separate evaluation profiles cannot be merged to inflate counterexamples.
- Two synthetic archived paired receipts that replay via the real `rsi::replayed_pair_metrics` mechanism select actual model/memory source files; changing one copied generation outcome without changing the original paired receipt invalidates the pair.
- Forging a different path, even after recomputing the proposal's own hash, fails source validation.
- Past-generation failures cannot forcibly select a repair on a different current source commit.

## What this does *not* prove

These are source changes and **synthetic unit-test fixtures**. They have not compiled or run in CI, and no hosted model multi-generation demonstration was performed. A negative-transfer hypothesis, detected damage and a selected repair are not evidence that a repaired successor truly improved. The next external evaluation must compare the actual post-edit source and newly rebuilt child on independent holdouts, then show that *its changed learning method* increases the productivity of further descendants.

All commits carry `[skip ci]`, consistent with the current project's 79-point prequalification gate.
