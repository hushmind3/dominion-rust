## 점검 범위

브랜치 변경 내용을 대상으로 대화 기록 조립, 참가자별 지속 컨텍스트, Codex HTTP/WebSocket 전송, 첨부 변환, 대화방 상태와 초기화, 교정 학습, 재시작 복구, 모델·추론 설정과 프런트엔드 연결을 검토했다. 저장소 전체 Rust 테스트와 Clippy, 프런트엔드 타입 검사·프로덕션 빌드, 배포 보조 스크립트 구문 검사도 실행했다.

기존 미추적 조사 문서·스크립트·임시 파일과 실제 서비스 데이터는 변경하지 않았다. 테스트는 별도 임시 데이터베이스와 모의 제공자를 사용했다.

## 발견 사항과 수정

| 우선순위 | 재현된 문제 | 수정 |
| --- | --- | --- |
| P1 | Codex 소켓의 수명 만료로 연결을 교체해도 이전 연결 기준의 전송 시작 위치가 남아, 새 연결에 과거 기록 없이 후속 질문만 전송됨 | 이전 응답 ID가 없는 연결에서는 전체 입력을 전송하고 전송 통계도 전체 모드로 기록 |
| P1 | Codex가 배열 형태의 사용자 콘텐츠를 빈 문자열로 처리해 이미지와 첨부 텍스트를 누락 | 텍스트·이미지 블록을 Responses 형식으로 변환하고 이미지 변경도 연결 기록의 동일성 검사에 포함 |

| P1 | 외부 채널의 인간 발언도 같은 사용자 메시지 원장을 사용하면서 주인의 확정 지시로 승격됨 | 외부 출처 메시지의 주인 상태 승격 차단. 이미 저장된 외부 출처 상태도 원본을 보존하면서 프롬프트에서 제외 |
| P1 | 시작하지 않은 프로그램 노드가 복구 허용 후에도 처리 중으로 남아, 실제 재개 단계에서 취소됨 | 작업 기록 검증을 통과한 체크포인트의 처리 중 표시를 해제. 미시작 노드는 미완료 상태를 유지하고 실제 진행 중·결과 불명 작업은 계속 검토 대상으로 유지 |
| P2 | 교정 이전 실행이 없으면 미래 실행을 대신 선택하고, 다른 참가자의 실행도 참조. 초 단위 메시지 시각 때문에 직후 교정을 놓침 | 미래 실행 대체 선택 제거, 실행을 에이전트별로 격리, 저장된 최종 답변과 교정 메시지의 원장 순서로 정밀한 선후관계 판단, 시각 비교는 파싱한 UTC 기준 사용 |
| P2 | 병렬 실행 테스트가 도구 실행 외의 부하까지 포함한 전체 요청 3.5초 제한 때문에 실패 | 실제 두 셸 연산의 시작·종료 구간이 겹치는지 검증하도록 변경 |
| P2 | 일반 CI는 Vite 빌드만 수행해 TypeScript 오류를 놓칠 수 있음 | CI에 `npm run typecheck --prefix web` 추가 |

Codex 소켓 대기 중 취소도 네트워크 응답 없이 처리하도록 개선했다. 사용하지 않는 방 라운드 카운터와 통합 테스트의 중복 변수도 제거했다.

## 검증 한계

- 실제 계정으로 OAuth 로그인·토큰 갱신·유료 모델 생성을 수행하지 않았다. 전송 검증은 로컬 모의 제공자를 사용했다.
