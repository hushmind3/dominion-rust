# 평가 프로필 확장

기본 네 가지 과제는 초기 평가 어댑터다. 범용 에이전트의 구성요소 목록·평가 목표를 그 과제에 영구 고정하지 않는다. 이 디렉터리에 운영자가 새 프로필과 독립 Rust oracle을 등록할 수 있다. 현재 어댑터는 **실제 소스 편집을 수행하는 후속 과제**를 평가한다. 일반 대화·웹/데스크톱 작업 전체를 평가하는 완성된 벤치마크라고 주장하지 않는다.

1. `default.json`을 `my-suite.json`으로 복사하고 `id`를 `my-suite`, `name`을 화면에 표시할 이름으로 바꾼다.
2. `requiredComponents`에 확인할 기존/새 역할을 지정한다. 이 값은 소스 변경 범위이며 지능 점수가 아니다.
3. `tasks`에 과제별 고유 id, 스케줄링 domain, 실제 file, request, oracle 테스트 이름, metric, guard 테스트 이름을 지정한다. 과제는 1~16개, 두 비교군에 동일하게 적용된다. domain은 현재 엔진의 memory/context/tools/learning/ui/improver 중 하나를 사용한다. 새 역할은 기존 스케줄링 분야에 매핑할 수 있다.
4. 프로필에 `"oracleFixture":"my-suite.rs"`를 추가하고 같은 디렉터리에 독립 Rust 평가 코드를 둔다. 기본 oracle의 형식은 `src/engine/rsi_oracle_fixture.rs`를 참고한다. 주 테스트의 이름은 `rsi_frozen_oracle::`로 시작해야 한다. 지표는 `quality`, `elapsedMs`, `contextChars`, `tokens` 중 선택한다.
5. 자기개선 고급 설정의 평가 목록을 새로고침하고 프로필을 선택한다. 잘못된 프로필은 `/api/rsi/evaluation-profiles`의 errors에 나타난다.

시작 API가 프로필과 oracle **실제 원문 전체**를 SHA-256과 함께 동결한다. 평가 중 파일을 바꾸거나 후손이 새로운 기준으로 자가 채점할 수 없다. 이어가기에서는 이전에 동결한 프로필을 사용한다. 새 과제/기준을 적용하려면 새 작업으로 시작한다. 비교 예산은 과제 수에 맞춰 두 실행기에 동일하게 나눈다. 각 과제의 회귀는 평균 성과로 상쇄하지 않는다.

`default`는 실행 파일에 포함된 기본 프로필이며 이 디렉터리의 파일 변경은 다음 빌드부터 적용된다. 사용자 프로필은 다른 id의 파일로 등록한다. 이 디렉터리와 평가기 코드는 후보 소스 편집의 허용 범위 밖에 있다.
